# Fireflydle 设计系统

## 视觉主张

“萤一把 / Fireflydle”采用安静、精密的深空视觉语言，不复刻游戏原界面。页面底色是一整片星点、星轨与星云构成的环境背景，内容以留白、信息带和清晰表格组织；主游戏棋盘是唯一视觉焦点。界面文案直接描述玩法和状态，避免用世界观名词包装普通操作。

本文件描述 **「星轨」重设计（v2）**，实现规格见 `docs/design/redesign-v2/README.md`，与原型 `docs/design/redesign-v2/prototype.html`、目标截图 `docs/design/redesign-v2/shots/` 配套。v1（“萤光”，`docs/design/redesign/`）已被取代。

正式角色图由网站版本发布流程同步；设计阶段不生成或仿制官方角色。

## 色彩

### 深色主题（默认）

- 画布：`#050817`（`--bg`）
- 主文字：`#f4f0e6`（`--ink`）
- 次文字：`#98a0ba`（`--muted`）
- 极弱文字：`#5b6483`（`--faint`）
- 分隔线：`rgb(214 222 255 / 9%)`（`--line`）、`rgb(236 226 205 / 18%)`（`--line-2`）
- 面板：`rgb(11 15 36 / 70%)`（`--panel`）、`rgb(13 17 40 / 95%)`（`--panel-2`）——**不用 `backdrop-filter`**，靠不透明度分层
- 星光金：`#f2cd7a`（`--lit`）——一致格 / 5★ / 品牌金
- 星云紫：`#9077ee`（`--near`）——接近格 / 4★
- 不符格：`rgb(170 185 255 / 8%)`（`--miss`）
- 主按钮：奶油金渐变 `linear-gradient(180deg, #fdf0d2, #e8c171)`（`--cta`）配深色文字 `#1d1406`（`--cta-ink`）
- 危险：`#ff7a85`

### 浅色主题

浅色由玩家显式切换（默认深色）。浅色下沿用同一套语义变量，`--lit` / `--near` 改为可读的深金与深紫，图鉴的命途 / 派系主题钩子（`:root[data-collection-theme]`、`:root[data-collection-faction]`）继续生效。

反馈状态必须同时配合字形，不能只依赖颜色：一致格带 `✓`，接近格带 `≈`，不符格带 `✗`，版本列带 `↑` / `↓`。

## 字体

- 全部界面文字使用同一族粗无衬线：`HarmonyOS Sans SC`, `MiSans`, `PingFang SC`, `Noto Sans SC`, `Noto Sans JP`, system-ui, sans-serif。**不再使用衬线大标题**。
- 数字与计时使用等宽字体并启用 `tabular-nums`（`.num` / `.tabular`）。
- 不依赖外部字体 CDN。

## 构图

- 顶部全局导航保持安静：品牌（金色四芒星 + 文字）、居中的胶囊导航、语言、公告、主题与账号。
- 总站是单页叙事：巨大的品牌粒子字占据首屏上半部，左下是每日入口与倒计时，右下是三项统计、昨日答案条与金色胶囊 CTA；下方依次是「开一局」四张模式卡、「换个玩法」三列圆角行、「本周」七列，最后是页脚状态条。
- 桌面游戏页使用窄左轨、宽棋盘、窄右轨；棋盘不是浮动卡片集合。
- 结果行使用圆角面板与细描边，状态用字形 + 颜色双重表达。
- 移动端将两侧信息折叠为棋盘上下的信息带，表格允许横向滚动并固定角色列。
- 页面最大内容宽度为 `1440px`，主阅读宽度为 `1180px`。

## 组件族

- `AppShell`：全局导航、语言、主题、账号状态、星空画布挂载点。
- `StarField` / `fx`：three.js 星空与覆盖层单例（`setText` / `setPortrait` / `burst` / `warp`），懒加载、可降级。
- `ModeShell`：由版本化内容 manifest 驱动的模式与活动页头积木。
- `ModeArt`：四个玩法卡的自绘 SVG 线稿，仅在卡片可见时运行，减少动效时完全静止。
- `RailPanel`：开放式信息轨，仅在功能确需分区时使用。
- `TicketButton`（类名沿用）：圆角胶囊，主按钮金色渐变、次按钮幽灵描边，明确的 hover/focus/pressed 状态。
- `GuessBoard`：固定表头、角色列、五项反馈字形、版本箭头。
- `CharacterCombobox`：键盘可操作、跨语言别名、虚拟化长列表。
- `InferenceReplay`：结算的候选头像葵花阵回放，提供「跳过」。
- `ResultReveal`：结算揭晓的点云汇聚 → 稀有度闪光 → 真实立绘淡入。
- `MetricStrip`：计时、剩余次数、比分与连接状态。
- `DataTable`：排行与后台复用，桌面表格、移动端紧凑列表。
- `Dialog` 与 `Drawer`：登录、规则、结算和移动端筛选。

## 动效与无障碍

- 页面转场 160–220ms，结果翻格错峰 105ms，结算回放每步 850ms，揭晓汇聚 1.6s。
- 遵循 `prefers-reduced-motion`，并支持 `?reduce` 与 `?nogl` 两个回归用降级开关；减少动效时直接显示最终状态，`?nogl` 时退回 CSS 渐变背景与 DOM 文字。
- 每帧固定 4 次绘制调用（星云、星点、星轨、星尘），逐帧运动全部在着色器里；页面隐藏时停止 rAF。
- 所有控件具有可见焦点环，触控目标至少 44px。
- 棋盘通过 `aria-live` 宣布新反馈，表格保留语义化表头；回放舞台对辅助技术隐藏，只保留计数器与跳过按钮。
- 深浅主题均满足正文 WCAG AA 对比度目标。

## 与设计文档的已知偏差

- 重设计文档建议用 CSS Modules 组织 `components/ui/`；本仓库沿用「`global.css` + 功能级 CSS + 语义类名」的既有体系，未引入第二套样式方案。
- 图鉴的命途 / 派系主题继续使用 v1 变量名（`--gold` / `--cyan` / `--border` 等）作为覆盖钩子，不改为 `--lit` / `--line`。
- 结算揭晓的立绘点云在构建期生成（`bun run assets:art`），共 90 个角色、平均约 5.7K 点 / 22KB。
