# Fireflydle：货币战争官方数据与猜测字段调研

调研日期：**2026-08-12（UTC+8）**。首次羁绊快照采于 2026-08-09，本文于 2026-08-12 扩展为完整玩法与数据源调研。

本文只使用 HoYoverse 官网、官方 HoYoWiki 及其第一方网页接口。每项结论均给出一手入口、接口或具体官方页面。网页接口公开可读不等于 HoYoverse 承诺 schema、内容或 ID 永久稳定，也不等于素材获得开放许可。

## 结论

1. **货币战争很适合成为 Fireflydle 的专题字段来源，不适合作为默认角色事实。** 费用、站位、定位、羁绊都是“货币战争”规则集下的玩法属性，会随赛季扩充和版本调整；必须显式标注为货币战争字段并绑定不可变 `rulesetId`。
2. **最适合猜测的是“费用”“站位”和“羁绊集合”。** 费用是 1–5 的有序单值，站位是前台/后台/前后台，羁绊是 1–3 个标签的多值集合。定位也可用，但官方词表并不规范，需先归一化成标签集合。
3. **当前官方 Wiki 不能完整自动生成全部角色字段。** 2026-08-12 从羁绊和专家顾问反向取得 66 个货币战争角色 ID，但只有 11 个英文详情和 5 个中文详情具备费用/站位/定位；日文详情只有名称，没有结构字段。其余角色只有名称与羁绊反向关系。
4. **羁绊本身结构最好。** 当前 29 个已发布羁绊详情均有类型、成员、激活阈值；共 143 条角色—羁绊引用、20 条羁绊装备引用、7 条专家顾问引用。羁绊必须建模为多值集合，不能拆成唯一阵营和唯一流派。
5. **六个菜单的三语完整度严重不对称。** 中文在投资策略、环境、羁绊、教学最完整；英文主要补角色和少量投资策略；日文主要补装备名称/说明。必须使用“各语言 ID 并集 + 按 ID 直读详情”，不能把某语言列表返回 0 当作条目不存在。
6. **官方内容会版本化变化。** 3.8 调整大量角色、羁绊、装备和策略；4.0 新增员工与专家顾问；4.2 新增“欢愉”并扩充环境、策略与敌方；4.3 仍在修复角色、羁绊和星徽交互。运行时直读 Wiki 会使历史答案漂移。
7. **装备、策略和环境适合独立专题，不适合角色猜测列。** 它们是对局物品或规则，不是角色固有属性；推荐装备覆盖也不完整、且受版本平衡影响。把它们塞进普通角色 GuessBoard 会产生大量 `unavailable` 和高强度泄题。

## 1. 官方玩法定义

### 1.1 上线、解锁和奖励

[3.7 版本更新说明](https://hsr.hoyoverse.com/zh-cn/news/160735)将“货币战争·零和博弈”定义为大型常驻玩法，开放条件为开拓等级 ≥ 21，并允许通过“终末视界”提前体验；官方建议完成匹诺康尼开拓任务“异乡异客”后体验。该公告明确列出变量骰子、自塑尘脂等奖励；同时说明可从该玩法获得深度沉浸器和助燃券。

该公告还说明 3.7 时货币战争与模拟宇宙积分奖励交替更新。[4.2 版本更新说明](https://hsr.hoyoverse.com/zh-cn/news/163625)则明确从 4.2 起合并货币战争与模拟宇宙积分，并调整部分积分线奖励；首期周期 5 日，之后恢复每周更替。

官方公开页面没有给出一个可稳定机器读取的完整奖励档位表。因此 Fireflydle 可以记录“玩法常驻、解锁等级和已明确点名的奖励种类”，但不应承诺当前每档奖励数值。

### 1.2 对局目标与总体流程

HoYoWiki“货币战争”教学菜单为 `menu_id=169`。以下规则分别来自具体官方教学页：

- [货币战争（entry 4158）](https://wiki.hoyolab.com/pc/hsr/entry/4158)：逐步招募团队，组成 8–10 人队伍，击败竞争对手。
- [位面与节点（entry 4187）](https://wiki.hoyolab.com/pc/hsr/entry/4187)：一局由 3 个位面构成；节点包括奖励、战斗、补给、遭遇和位面首领。
- [商店（entry 4190）](https://wiki.hoyolab.com/pc/hsr/entry/4190)：节点备战阶段商店自动刷新；玩家用金币购买角色，也可付费刷新或锁定商店。
- [金币（entry 4143）](https://wiki.hoyolab.com/pc/hsr/entry/4143)与[金币·利息（entry 4191）](https://wiki.hoyolab.com/pc/hsr/entry/4191)：金币用于购买角色、升级团队规模和刷新商店；节点收入由基础金币、连胜和利息组成，利息上限为 5 金币。
- [等级·团队规模（entry 4189）](https://wiki.hoyolab.com/pc/hsr/entry/4189)：战斗或购买经验提升等级，进而提高团队规模。
- [角色·星级（entry 4146）](https://wiki.hoyolab.com/pc/hsr/entry/4146)：3 个相同星级角色自动升星；3 星通常是最强形态，升星同时强化数值与角色赋能。
- [装备（entry 4156）](https://wiki.hoyolab.com/pc/hsr/entry/4156)与[装备·合成（entry 4157）](https://wiki.hoyolab.com/pc/hsr/entry/4157)：每名角色最多穿戴 3 件装备；任意两件简易装备可以合成进阶装备。
- [羁绊（entry 4160）](https://wiki.hoyolab.com/pc/hsr/entry/4160)：招募并上阵具有相同羁绊的角色会提高羁绊等级和效果。
- [战斗·胜利规则（entry 4147）](https://wiki.hoyolab.com/pc/hsr/entry/4147)：倒计时归零前消灭所有敌人为胜利，否则小队受到伤害。
- [小队生命值（entry 4154）](https://wiki.hoyolab.com/pc/hsr/entry/4154)：初始 100 点；失败会扣除，降至 0 时本局失败；结束时剩余生命决定评价。

可以将当前官方流程概括为：

```text
选择模式/难度
→ 进入三个位面之一
→ 节点备战：商店招募、升星、升级团队规模、装备/合成、调整站位
→ 节点战斗：倒计时内击败敌人
→ 获得金币、经验、物品或失去小队生命
→ 激活/提高羁绊并继续构筑
→ 击败位面首领
→ 完成三个位面并按剩余生命结算评价/职级
```

### 1.3 角色专属机制

- [角色·费用（entry 4145）](https://wiki.hoyolab.com/pc/hsr/entry/4145)：角色购买价分为 1–5 费；官方教学称总体初始战力为 5 费 > 4 费 > 3 费 > 2 费 > 1 费，同费用角色近似。
- [角色·站位（entry 4141）](https://wiki.hoyolab.com/pc/hsr/entry/4141)：站位为前台、后台或前后台。
- [角色·赋能（entry 4148）](https://wiki.hoyolab.com/pc/hsr/entry/4148)：角色在正确站位时获得货币战争专属能力；前台通常强化角色本体技能，后台角色自动攻击或辅助。
- [角色·养成与试用（entry 4161）](https://wiki.hoyolab.com/pc/hsr/entry/4161)：已拥有的角色继承玩家养成数据，未拥有的角色使用对应试用角色。
- [角色·数值映射（entry 4142）](https://wiki.hoyolab.com/pc/hsr/entry/4142)：未达到养成标准的角色会被系统自动强化并显示映射标记。
- [战斗·自动秘技（entry 4184）](https://wiki.hoyolab.com/pc/hsr/entry/4184)：前台角色自动使用秘技；若效果无法同时激活，只取站位最靠左的首个角色。

因此“费用、站位、定位/赋能”是货币战争自己的事实，不能覆盖普通角色的稀有度、命途或常规战斗定位。

### 1.4 模式与职级

- [标准博弈（entry 4171）](https://wiki.hoyolab.com/pc/hsr/entry/4171)：常规模式，可自由选择职级难度；职级越高，难度和奖励越高，通关可晋级。
- [职级（entry 4159）](https://wiki.hoyolab.com/pc/hsr/entry/4159)：成功挑战当前最高职级难度时，根据剩余小队生命值获得评价并提升职级。
- [职级·晋升规则（entry 4172）](https://wiki.hoyolab.com/pc/hsr/entry/4172)：结算生命不低于 70 提升 3 级，不低于 40 提升 2 级，低于 40 提升 1 级；失败不降职级。
- [超频博弈（entry 4155）](https://wiki.hoyolab.com/pc/hsr/entry/4155)：用时更短，可完成周期积分任务，可自选难度，但通关不提升职级。
- [超频博弈·规则（entry 4153）](https://wiki.hoyolab.com/pc/hsr/entry/4153)：每个位面节点更少；每节点自动获得更多经验和金币，但不再获得利息。

官方教学没有为这些模式提供稳定的枚举 API；Fireflydle 若引用模式，应维护项目自己的 `standard` / `overclock` 稳定 ID，并保存对应教学页 ID。

## 2. 第一方接口与抓取方法

官方入口为 [HoYoWiki HSR](https://wiki.hoyolab.com/pc/hsr/home)，API base 为：

```text
https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/
```

[菜单接口 `get_menus`](https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/get_menus)当前返回：

```text
货币战争 menu_id=163
├─ 角色     menu_id=164
├─ 装备     menu_id=165
├─ 投资策略 menu_id=166
├─ 投资环境 menu_id=167
├─ 羁绊     menu_id=168
└─ 教学     menu_id=169
```

另有教学目录下同名的 `menu_id=182`，2026-08-12 列表为 0。它不是上述货币战争图鉴菜单，不能混用。

可复现请求：

```text
GET  get_menus
GET  get_menu_filters?menu_id=<menuId>
POST get_entry_page_list
GET  entry_page?entry_page_id=<entryId>
GET  search?keyword=<query>
```

分页列表请求体：

```json
{
  "filters": [],
  "menu_id": "168",
  "page_num": 1,
  "page_size": 50,
  "use_es": true
}
```

请求需带 HoYoWiki 网页使用的 `x-rpc-wiki_app: hsr`、`x-rpc-language` 和 `x-rpc-client_type: 4` 等头。详情中的 `baseInfo`、画廊和自定义内容又是 JSON 字符串，必须先解析 JSON，再使用 HTML 解析器处理富文本；不能用正则直接生产数据。

## 3. 六类菜单的数据质量

### 3.1 2026-08-12 原始计数

“列表数”来自每种语言完整分页；“并集”是三语 `entry_page_id` 并集；“结构详情”表示按并集 ID 直读后 `baseInfo` 非空。

| 菜单           | 中文列表 | 英文列表 | 日文列表 | ID 并集 | 中文结构详情 | 英文结构详情 | 日文结构详情 |
| -------------- | -------: | -------: | -------: | ------: | -----------: | -----------: | -----------: |
| 角色 `164`     |        5 |       11 |        0 |      11 |            5 |           11 |            0 |
| 装备 `165`     |       16 |        0 |       79 |      79 |           16 |            0 |           79 |
| 投资策略 `166` |      266 |       83 |        0 |     266 |          266 |           83 |            0 |
| 投资环境 `167` |       72 |        0 |        0 |      72 |           72 |            0 |            0 |
| 羁绊 `168`     |       29 |        0 |        0 |      29 |           29 |            0 |            0 |
| 教学 `169`     |       47 |        0 |        0 |      47 |            0 |            0 |            0 |

教学内容位于画廊 `imgDesc`，所以 `baseInfo=0` 不代表无内容。按 ID 直读时，所有并集 ID 在三语均能返回本地化名称；但名称可读不等于正文和结构完整。例如英文、日文羁绊详情只有标题，正文为空。

这组数据证明正确同步算法必须是：

```text
各语言完整分页
→ 取 entry_page_id 并集
→ 每种语言按 ID 直读详情
→ 分别统计 name / baseInfo / rich text / source version 覆盖
→ 仅从实际有值的语言读取事实
→ 用稳定 ID 关联本地化名称
```

### 3.2 角色 `menu_id=164`

[角色筛选器](https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/get_menu_filters?menu_id=164)公开以下枚举：

- 费用：1、2、3、4、5 费与专家顾问；
- 阵营羁绊：13 个筛选值；
- 流派羁绊：12 个筛选值；
- 其他：7 个筛选值。

详情 `baseInfo` 的实际字段为名称、费用、站位、定位、羁绊、推荐装备；部分推荐装备按前台/后台分别列出。详情还包含角色技能和角色信息详情等富文本模块。

但列表端点当前只有 11 个 ID 的并集，远少于羁绊详情反向引用的 66 个角色。不能用 `menu_id=164` 列表作为货币战争角色全集；应以所有羁绊成员和专家顾问引用生成候选全集，再逐 ID 读取角色详情。

66 个反向角色中：

- 11 个有费用、站位和定位（来自英文 11 条与中文 5 条的并集）；
- 55 个只有名称和羁绊关系，缺少上述结构字段；
- 中文详情只覆盖费用分布 2 费 ×1、3 费 ×2、4 费 ×1、5 费 ×1；合并英文后也仍不足以代表全池。

因此费用/站位/定位尚不能直接覆盖整个货币战争角色池。它们可以先作为“字段完整白名单”中的专题列，或等待官方详情补齐。

### 3.3 装备 `menu_id=165`

[装备筛选器](https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/get_menu_filters?menu_id=165)给出 7 类：简易装备、进阶装备、特权装备、星徽、羁绊装备、消耗品、其他装备。

三语并集为 79 个 ID，但结构分裂明显：

- 中文 16 条提供名称、类型、实装版本；其中 2 条还有基础效果、装备效果、适配角色和合成公式，16 条均标为 3.7；
- 日文 79 条提供名称，77 条提供说明；
- 英文名称可按 ID 读取，但 `baseInfo` 为空。

所以装备名称和日文说明较完整，但完整类型、配方、效果和适配关系无法从单一语言全量得到。装备适合做独立图鉴/图片专题，不适合作为角色猜测字段或推荐装备事实源。

### 3.4 投资策略 `menu_id=166`

[投资策略筛选器](https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/get_menu_filters?menu_id=166)提供：

- 稀有度：银色、金色、棱彩；
- 出现位面：位面 1、2、3，可多值。

中文 266 条全部具备名称、稀有度和出现位面：

- 银色 48；
- 金色 115；
- 棱彩 103。

出现位面组合分布为：位面 1 共 62、位面 2 共 26、位面 3 共 14、1+2 共 21、2+3 共 29、1+2+3 共 112，另有 2 条官方文本括号错误。具体错误为：

- `entry_page_id=4609`“保守派”：`位面[1]，位面[2]，位面{3]`；
- `entry_page_id=4602`“三五成群”：`位面{2]，位面[3]`。

英文结构只覆盖 83 条，日文详情标题可读但结构为空。中文名称没有重复，但没有结构化策略效果；因此只能安全同步名称、稀有度和出现位面，不能根据当前 Wiki 自动实现策略效果或公平的“效果猜测”。

### 3.5 投资环境 `menu_id=167`

中文列表有 72 条，无筛选器。详情稳定字段只有名称，以及可选的“关联条目”：

- 49 条含关联引用；
- 共 91 个引用；
- 其中 45 指向货币战争角色、37 指向装备、4 指向背包物品、5 个引用缺少菜单 ID。

例如 [红钻贵族（entry 4963）](https://wiki.hoyolab.com/pc/hsr/entry/4963)关联红钻与简易武装箱；“特邀专家：加拉赫”关联加拉赫和以太钻头；各种“羁绊邀请”关联对应星徽。

当前详情没有结构化效果正文，也没有类型枚举。环境名称通常直接泄露关联对象，且跨语言正文为空；更适合做“环境→关联对象”的独立专题，不适合放进角色 GuessBoard。

### 3.6 羁绊 `menu_id=168`

29 条中文详情全部具有：羁绊名称、羁绊类型、羁绊角色、羁绊分级。另有：

- 21 条声明羁绊装备，合计 20 个非空引用；
- 6 条声明专家顾问，合计 7 个引用；
- 29 条均有基础效果；28 条有“羁绊分级效果”，另一条使用“基础分级效果”。

这是六个菜单中最适合作为 Fireflydle 结构字段的数据集。

### 3.7 教学 `menu_id=169`

中文当前 47 条，覆盖核心循环、经济、商店、角色、装备、羁绊、战斗、职级、标准/超频模式和进阶技巧。正文位于画廊 JSON 的 `imgDesc`，而不是 `baseInfo`。

英文和日文列表为空，但按同一 ID 可以读取本地化标题与页面版本；当前正文完整度不足，不能以三语正文作为自动规则说明来源。Fireflydle 应人工翻译最小必要的规则摘要，并保留中文教学页为证据，不复制整篇教程。

## 4. 货币战争独立单位

羁绊详情中的成员全部引用 `menuId=164`，不是普通可玩角色 `menu_id=104`。因此货币战争单位具有自己的 ID 命名空间。

当前反向候选包括：

- 普通可玩角色，如三月七、姬子、卡芙卡；
- 官方合作角色 Saber、Archer；
- 同人物的独立可玩形态，如丹恒·饮月、丹恒·腾荒；
- 不同实体名但剧情关联的角色，如黑塔与大黑塔；
- 货币战争专用或后续形态，如火花、绯英、银狼 LV.999；
- 泛称“开拓者”，没有指定 Fireflydle 中的某个命途形态。

[4.3 版本更新说明](https://hsr.hoyoverse.com/zh-cn/news/164415)明确把“银狼 LV.999（欢愉·虚数）”作为货币战争角色，同时另行提到专家顾问“银狼（虚无·量子）”。这证明货币战争必须按自己的单位 ID 和名称处理。

产品于 2026-08-15 确认：货币战争模式不需要对应普通角色，直接使用独立数据集：

```ts
type CurrencyWarsUnit = {
  id: CurrencyWarsUnitId;
  rulesetId: string;
  names: LocalizedText;
```

### 5.2 多值性

2026-08-12 当前详情共有 143 条成员引用，反向映射到 66 个货币战争角色；同一角色可有 1–3 个羁绊，并存在：

- 两个流派 + 一个阵营；
- 一个流派 + 两个阵营；
- 一个独立 + 一个流派 + 一个阵营；
- 一个独立 + 两个阵营；
- 只有单个流派或单个独立。

正确结构是：

```ts
currencyWarsBondIds: BondId[];
```

而不是唯一 `factionBondId` 和 `schoolBondId`。类型只用于分组，不能限制成员基数。

### 5.3 星徽和专家顾问会改变局内计数

[稀有装备·星徽（entry 4179）](https://wiki.hoyolab.com/pc/hsr/entry/4179)说明，给非羁绊角色穿戴星徽会令其加入对应羁绊并增加计数。因此必须区分：

- `nativeBondIds`：角色图鉴中的原生羁绊，可用于 Fireflydle；
- `effectiveBondIds`：某一局因装备、顾问等临时获得的羁绊，只属于对局状态，不能用于角色静态猜测。

专家顾问也是羁绊详情中的独立引用关系，不应和原生成员合并。否则青雀、停云、加拉赫等会被错误标为所有顾问关联羁绊的原生成员。

### 5.4 官方不一致

- 角色筛选器和“列车同行”详情基本信息把它归为阵营羁绊，但羁绊列表的 `filter_values` 曾错误标为流派羁绊。应以详情基本信息和官网公告语义为准，并保留 override。
- 筛选器写“追加攻击”，详情名为“追击”；英文均为 `Follow-Up ATK`，日文均为“追加攻撃”。必须合并到一个永久 ID。
- 角色列表筛选器含 32 个标签，但其中“命运圣杯”“头号玩家”“领航员”只有可搜索的三语空壳页（分别为 10161、5520、10160），未进入 29 个完整羁绊详情。不能纳入正式成员判题。

## 7. 数据一致性、稳定 ID 与版本冻结

### 7.1 当前观察到的不稳定性

- 语言列表完全不同步，例如装备中文 16、英文 0、日文 79；按相同 ID 直读又通常能取得三语标题。
- 2026-08-09 同日重复读取羁绊详情曾得到 63 和 66 个唯一角色；2026-08-12 再次得到 66。公开接口无法证明是边缘缓存、内容发布还是其他原因。
- Wiki `version` 更像页面修订时间戳；部分语言详情返回 `version=0`，不能当游戏版本。
- 投资策略已有两处官方字符串格式错误，说明 schema 正确不代表值无需校验。

### 7.2 推荐抓取策略

1. 对每种语言完整分页，保存原始 JSON、URL、请求体、抓取时间和 SHA-256；
2. 合并所有语言的 `entry_page_id`，逐 ID 读取详情；
3. 将列表、详情、结构字段、本地化名称分别做覆盖率报告；
4. 在相隔一段时间的两次抓取结果一致后才生成候选发布快照；
5. 对新增、删除、成员变化、阈值变化、分类变化和三语缺失生成 diff；
6. 人工确认后发布自己的 `rulesetId`；
7. 历史题目、周赛和好友挑战永久引用创建时的 `rulesetId`。

### 7.3 稳定 ID

官方可见标识包括：

- 条目 `entry_page_id`；
- 筛选值 numeric ID；
- 筛选值 `mi18n_key`；
- 页面 `version`。

`entry_page_id` 是当前最强跨语言关系键，但仍无公开稳定契约。Fireflydle 应分配永久 ID，并把官方 ID 作为来源映射：

```ts
type SourceRef = {
  source: "hoyowiki" | "hoyoverse-news";
  menuId?: string;
  entryPageId?: string;
  filterValueId?: string;
  mi18nKey?: string;
  newsId?: string;
  url: string;
  fetchedAt: string;
  responseSha256: string;
};
```

## 9. Fireflydle 猜测字段建议

### 9.1 推荐字段

| 字段            | 建议         | 判题语义                                               | 前提                                           |
| --------------- | ------------ | ------------------------------------------------------ | ---------------------------------------------- |
| 货币战争费用    | 专题模式可用 | `exact` 同费用；`close` 可用高/低方向提示；`miss` 不同 | 入池角色费用覆盖 100%                          |
| 货币战争站位    | 专题模式可用 | 单值/枚举比较；`flex` 与前台或后台可定义 `close`       | 入池角色站位覆盖 100%，规则说明明确            |
| 货币战争定位    | 谨慎使用     | 归一化标签集合；集合相等/交集/无交集                   | 先定义稳定 role taxonomy；不能直接比较自由文本 |
| 原生羁绊集合    | 强烈推荐     | 集合相等为 `exact`，有交集为 `close`，无交集为 `miss`  | 绑定规则快照，只用原生成员                     |
| 羁绊类型        | 只作 UI 分组 | 不单独判题                                             | 类型过宽，信息量低                             |
| 羁绊激活阈值    | 羁绊专题可用 | 有序数组完全一致或结构化比较                           | 猜测对象必须是羁绊，不是角色                   |
| 策略稀有度/位面 | 策略专题可用 | 枚举与集合比较                                         | 不与角色题池混用                               |
| 装备类型/配方   | 装备专题候选 | 类型 exact；配方集合比较                               | 当前全量结构覆盖不足，暂不上线                 |

### 9.2 羁绊判题

```ts
type CurrencyWarsBondGuess = {
  fieldId: "currency-wars-bonds";
  rulesetId: string;
  bondIds: BondId[];
};
```

| 结果          | 条件                                              |
| ------------- | ------------------------------------------------- |
| `exact`       | 猜测角色与目标角色的 `nativeBondIds` 集合完全相等 |
| `close`       | 集合不同，但至少有一个共同原生羁绊                |
| `miss`        | 两个币战单位均有可信集合，且集合无交集            |
| `unavailable` | 任一单位字段不完整，或两个单位属于不同规则快照    |

不能因为两个标签同属阵营/流派就判 `close`。UI 应逐项展示羁绊 chip 的交集，而不是只显示一个聚合颜色。

### 9.3 不公平或泄题风险

1. **独立羁绊几乎直接泄露答案。** 当前 5 个完整独立羁绊均只有 1 名成员；它们只适合专家/专题模式，或在展示时降权/隐藏名称。
2. **模式专用名字只在币战题池中使用。** “银狼 LV.999”等名称不与普通角色题池共用候选，避免两个命名空间混在同一局。
3. **推荐装备会受到平衡调整且覆盖不足。** 不应当作正式角色事实。
4. **角色赋能正文往往高度专属。** 适合能力描述猜角色的独立玩法，不适合作为 Wordle 式比较列。
5. **策略/环境名称常直接包含羁绊或角色名。** 例如“战技点邀请”“特邀专家：加拉赫”，不能和答案同时无处理展示。
6. **费用天然近似强度。** 作为有序字段时可以给高/低方向，但不能把相邻费用自动视为语义相近角色。
7. **缺失字段绝不能判 `miss`。** 当前 66 个反向角色中只有 11 个具备费用/站位/定位；未覆盖角色必须排除该字段题池或返回 `unavailable`。

### 9.4 推荐产品边界

- 默认每日题和标准 ELO：不启用货币战争字段；
- 普通可玩角色、NPC 和星神模式：不启用货币战争字段；
- 独立货币战争模式：首发使用费用、站位和羁绊三列，只使用字段完整的币战单位子集；
- 羁绊图鉴专题：猜羁绊类型、阈值、成员和星徽；
- 策略/装备专题：待三语和结构覆盖达标后独立上线；
- NPC 和星神题池：不继承货币战争字段，也不与 `menu_id=164` 单位建立运行时映射。

## 10. 发布验收门槛

货币战争字段启用前应全部满足：

1. 每个正式币战单位有稳定项目 ID、来源 ID 和当前启用字段；
2. 费用、站位和原生羁绊在目标与候选子池中均可正常判定；
3. 空壳羁绊和字段缺失单位不进入对应正式子池；
4. 对费用方向、站位、羁绊集合相同/相交/不交建立基本规则样例；
5. 对局保存 `rulesetId`，历史结果不受新版本影响；
6. UI 明确标注“货币战争”语境，避免玩家误认为这些是常规角色设定。

## 11. 版权、素材与不确定性
