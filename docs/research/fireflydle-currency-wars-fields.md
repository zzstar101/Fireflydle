# Fireflydle：货币战争可扩展字段调研

调研日期：**2026-08-15（UTC+8）**

本次调研只采用 HoYoverse 官方公告、官方 HoYoWiki 页面和 HoYoWiki 第一方接口。覆盖率数字来自仓库中的货币战争快照（2026-08-12）；2026-08-15 重新读取了角色筛选接口和规则教学页，用于确认枚举和字段语义。公开接口没有稳定 schema 承诺，因此以下结论是当前快照的工程判断，不是 HoYoverse 的长期保证。

## 结论先行

Q60 可以扩展，但不应把所有出现在角色详情或教学中的内容都变成 GuessBoard 列。推荐的可玩扩展顺序是：

1. **原生羁绊集合**：继续作为核心字段，覆盖当前反向角色全集。
2. **费用**：最适合扩展的数值字段，1–5 费，有明确顺序。
3. **站位**：适合扩展的离散字段，前台、后台、前后台。
4. **定位标签**：有玩法价值，但先做少量受控标签；官方详情目前是自由文本，不能直接上线。
5. **羁绊类型/羁绊数量**：可作为界面辅助信息或羁绊专题字段，不建议与羁绊集合并列成另一列。

星级、赋能正文、推荐装备、角色技能关键词和专家顾问关系应先保留为题库数据或独立专题，不作为 v1.0 角色 GuessBoard 的默认判题列。它们要么是局内状态，要么是自由文本/版本敏感关系。

这里的“覆盖率门槛”只针对准备启用的**币战子池**，不是要求官方反向发现的全部角色都补齐所有字段。缺字段的角色可以留在关系图或候选资料中，但不能进入启用该字段的目标/猜测子池。这样可以扩展字段，同时不把一个小网站变成内容审核系统。

## 可扩展字段的具体方案

### 1. 原生羁绊集合（现在就能扩展）

继续使用：

```ts
type CurrencyWarsStaticFields = {
  nativeBondIds: BondId[];
};
```

判题保持集合语义：集合完全相等为 `exact`；有交集但不完全相等为 `close`；两边都有可靠集合且无交集为 `miss`。反馈不显示共享羁绊的具体名称、ID 或数量。只读取角色图鉴的原生成员关系，不把星徽或专家顾问在局内产生的临时关系写入角色静态字段。

### 2. 费用（最值得扩展）

费用是明确的 1–5 单值，适合提供方向提示：目标比猜测更高、相同或更低。不要把相邻费用自动判为语义 `close`，因为官方只说明整体战力层级，并没有角色间“接近”的定义。

建议字段：

```ts
cost: 1 | 2 | 3 | 4 | 5;
```

只在费用完整的币战子池中启用。每日/标准角色题不显示此字段。

### 3. 站位（值得扩展）

官方枚举可收敛为：

```ts
position: "front" | "back" | "flex";
```

`front`、`back` 只做 exact/miss；`flex` 是否对任一单站位返回 close，必须在 UI 和规则说明中固定。为保持小网站规则简单，建议首版只做 exact/miss，避免“前后台”被误解成两个独立值。

### 4. 定位/赋能（有潜力，但先做轻量归一化）

官方详情中定位/赋能目前是描述文本，而不是稳定枚举。可先保存原文和手工标签，但不要为了填满 66 个单位而强行推断。若未来要启用，可采用 6–8 个玩家易懂的受控标签，例如：

`damage`、`survival`、`healing`、`shield`、`energy`、`debuff`、`follow-up`、`utility`。

标签允许多值；只有所有进入该专题子池的单位都有人工确认标签后才启用。标签应绑定 `rulesetId`，因为官方 3.8/4.3 公告已证明角色赋能会调整。

### 5. 羁绊类型与数量（辅助信息）

角色的羁绊类型不是唯一值。可以在详情或结果页显示“阵营/流派/独立”的分组数量，但不建议再加一列与 `nativeBondIds` 并列判题：这会重复表达同一关系，且让玩家从类型数量反推答案。

## 暂不扩展为角色 GuessBoard 列的字段

### 星级

官方教学定义的是“3 个相同星级角色自动升星”，星级随每局招募和合成变化。将它作为角色静态属性会把局内状态误当成答案事实。若未来做“币战局面猜测”专题，可以把星级放入对局状态；不要放进角色题池。

### 赋能正文和技能关键词

赋能内容是说明文本，且受站位和版本影响。直接显示正文会很容易泄露答案；人工抽取技能关键词又会引入自定义分类。保留原文来源即可，等以后确实要做“根据能力猜角色”的独立模式再设计。

### 推荐装备

推荐装备是版本策略建议，不是角色固有关系；当前角色详情覆盖不全，装备列表本身也存在语言和结构不对称。可以做独立的“装备→角色”图鉴，但不应在角色 GuessBoard 中作为判题列。

### 专家顾问

“专家顾问”是角色菜单的官方筛选类别和羁绊详情中的引用关系。它适合控制 NPC/顾问候选池或做玩法图鉴，不应作为每个角色的普通 GuessBoard 字段；否则普通成员会得到大量空值或产生错误的“不是顾问”反馈。

## 轻量上线建议

不要要求全官方宇宙先达到所有字段完整。可以维护一个版本化的 `currency-wars` 子池：

```text
角色反向发现全集
→ 确认币战单位 ID 与来源
→ 选择本次启用字段
→ 仅将该字段齐全的单位放入子池
→ 费用/站位/羁绊先上线
→ 定位标签达到可接受规模后再加
```

同步脚本只需输出字段覆盖报告和缺失列表；一次人工确认后生成 manifest。每日题使用固定日期种子，随机题直接随机，不需要玩家历史去重、复杂审核状态或多角色审批流。历史题目只保存创建时的 `rulesetId`，保证官方版本更新不改写旧结果。

## 建议给 Q60 的扩展选项

若要把 Q60 从“费用、站位、羁绊”继续扩展，优先考虑：

1. **定位标签**：价值最高，但必须先建立小型受控词表并限定在完整子池。
2. **羁绊类型分组**：作为视觉分组或羁绊专题字段，不另判角色类型。
3. **费用方向提示**：不是新列，但能让费用字段更有猜测感。
4. **站位兼容规则**：明确 `flex` 的反馈，不增加字段数量却提高可玩性。

不建议为 v1.0 扩展星级、赋能正文、推荐装备、技能关键词或专家顾问列；这些内容可以继续采集，但保持为元数据/独立专题。
