# 货币战争题库重建核对（2026-08）

## 结论

按用户提供的 BWiki 页面重新读取了货币战争角色表。页面当前包含 72 条角色记录，覆盖版本 `3.7`、`4.0`、`4.2` 和 `4.4`。当前仓库的 8 个币战单位都能在该表中找到，因此没有发现普通角色误混；但 8 个单位的费用、站位或羁绊字段均存在差异，不能继续作为 `approved` 正式数据。

重建时应以角色表的原始条目为准，并保留以下两个不同实体：

- `银狼`：3.7 条目，费用 4，站位前后，羁绊为星核猎手、量子同频。
- `银狼LV.999`：4.2 条目，费用为 3/4/5 多值，站位前，羁绊为头号玩家、星核猎手、欢愉。

因此，`银狼LV.999` 不能被压缩成普通单值费用，也不能覆盖普通 `银狼` 的数据。

## 来源与方法

- 主核对来源：BWiki《[角色一览（货币）](https://wiki.biligame.com/sr/%E8%A7%92%E8%89%B2%E4%B8%80%E8%A7%88%EF%BC%88%E8%B4%A7%E5%B8%81%EF%BC%89)》；页面由用户直接提供，读取日期为 2026-08-18。
- 页面 HTML 中的 72 个 `<tr class="divsort">` 记录作为条目边界。
- 每条记录的 `data-param2` 为站位、`data-param3` 为羁绊集合、`data-param6` 为费用、`data-param7` 为版本；角色名称取角色链接标题。
- BWiki 是社区维护资料，不等同于官方 API。本文只记录页面当前事实；上线前应在数据审核中固定抓取时间和页面版本。

### 题池范围差异

- BWiki 页面：72 条目。
- 当前 manifest `candidateIds`：8 条；`targetIds`：6 条（流萤、黄泉、砂金、卡芙卡、花火、银狼）。
- 黑塔和刃只作为当前候选，不能作为答案；这不是页面数据要求，而是当前产品配置。
- 目前没有把其余 64 条角色导入实体表，且 `entities` 为空；因此 API 搜索和题目选择无法覆盖 BWiki 的完整货币战争角色表。

## 重建要求

1. 先把 72 条记录导入独立的币战实体数据，不复用普通角色实体，也不把 BWiki 角色名直接当作普通模式 ID。
2. 费用字段支持 `number | number[]`；`银狼LV.999` 必须保存为 `[3,4,5]`，并明确费用比较规则（猜测值与答案多值的命中/方向反馈）后再开放入池。
3. 站位统一映射为 `front`、`back`、`front-back`，不能把 `前` 或 `前后` 当作同一值。
4. `synergies` 保存条目中全部羁绊，作为无序集合比较；不要退化成单一阵营字段。页面当前去重后共出现 32 个羁绊名称，需先建立稳定 ID 和中文显示名。
   去重后的名称为：列车同行、领航员、减益、星核猎手、燃血、命运圣杯、能量、战技点、头号玩家、欢愉、星间旅人、巡海游侠、追击、仙舟、击破、盛会之星、大守护者、贝洛伯格、群攻、魔术师、狼狩、公司、命运卜者、持续伤害、夜之半神、挚爱之人、昼之半神、银河学者、治疗、量子同频、护盾、救世主。
5. 版本字段应保留在单位数据中。当前 3.7 是主体，4.0、4.2、4.4 是后续版本，不能在无版本选择的情况下混合成一个无法复现的池。
6. 在逐条完成名称、费用、站位、羁绊、版本和资源审核前，所有新导入单位保持 `draft`/`needs-review`，不要标记为 `approved`，也不要让它们进入正式目标池。
7. 对 `银狼` 与 `银狼LV.999` 使用不同稳定 ID；对 `姬子` 与 `姬子•启行`、`刃` 与 `千冶•刃`、不同开拓者形态同样如此。
