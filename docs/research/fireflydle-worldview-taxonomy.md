# Fireflydle 普通世界观字段调研

> 快照日期：2026-08-12。本文只使用 HoYoverse 官网、官方 HoYoWiki 及其第一方网页接口。接口公开可读不代表 HoYoverse 承诺 schema、内容或 ID 永久稳定。

## 结论摘要

1. **不要建立笼统的“身份标签”。** HoYoWiki NPC 的 `身份` 虽然有较高覆盖，但它混合职位、物种、会员编号、状态和玩笑文本，不是可枚举的世界观分类。`无名客`、`自灭者`、`石心十人`均有官方派系页，应作为派系候选，而不是身份标签。
2. **角色菜单的 `character_factions` 不能直接当作派系或地区。** 当前 90 个条目中 81 个恰有一个值、9 个为空、没有多值；但它的 21 个枚举混合 9 个地点/世界、10 个组织/群体和 2 个兜底类别。
3. **NPC 列表更像“所在内容区域”，详情 `阵营`更像人物归属，但二者都不稳定。** 436 条 NPC 中，列表阵营与详情阵营各覆盖 429 条；54 条字符串不一致，其中 51 条只是空间站名称写法不同，3 条是实质冲突。
4. **官方派系菜单是派系词典，不是成员数据库。** `menu_id=120` 有 36 个中文条目，但只有 7 页在任意富文本中引用可玩角色；“关联条目”没有关系类型，既可能表示上下级，也可能表示敌对或一般相关。
5. **地区和派系必须分开，但不能全自动分开。** 官方没有统一的“角色唯一地区”字段。Fireflydle 可以发布唯一 `regionId` 和唯一 `factionId`，但两者都是经过证据审核的游戏规则字段，不应伪装成官方原始字段。
6. **普通模式最小模型只需要地区与派系。** 不加入 `identityTagIds`；货币战争羁绊仍是完全独立的版本化字段。派系层级只接受人工审核的明确边，`close` 不从官方无类型关联自动推断。

## 一手来源和复现方法

官方入口为 [HoYoWiki HSR](https://wiki.hoyolab.com/pc/hsr/home)，第一方网页 API base 为：

```text
https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/
```

本次使用：

- [`get_menus`](https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/get_menus)
- [`get_menu_filters?menu_id=104`](https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/get_menu_filters?menu_id=104)
- [`get_menu_filters?menu_id=105`](https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/get_menu_filters?menu_id=105)
- [`get_menu_filters?menu_id=120`](https://sg-wiki-api.hoyolab.com/hoyowiki/wapi/get_menu_filters?menu_id=120)
- `POST get_entry_page_list`
- `GET entry_page?entry_page_id=<id>`

列表请求体为：

```json
{
  "filters": [],
  "menu_id": "104",
  "page_num": 1,
  "page_size": 50,
  "use_es": true
}
```

请求使用网页客户端相同的 `x-rpc-wiki_app: hsr`、`x-rpc-language: zh-cn`、`x-rpc-client_type: 4`、Origin 和 Referer。详情模块中的 `data` 是 JSON 字符串，部分字段值又包含 HTML 或 `$[...]$` 包裹的引用对象，因此生产同步必须先解析 JSON，再解析结构化引用和 HTML。

## 1. 可玩角色的 `character_factions`

### 1.1 实际基数

2026-08-12 中文 `menu_id=104` 返回 90 个角色形态：

|   值数量 | 条目数 |  占比 |
| -------: | -----: | ----: |
|        0 |      9 | 10.0% |
|        1 |     81 | 90.0% |
| 2 或更多 |      0 |    0% |

当前缺失阵营的 9 个条目为绯英、不死途、爻光、阿格莱雅、星期日、波提欧、知更鸟、真理医生、银枝。

因此，**当前快照的数据实际上是单值或缺失**。但筛选器的 `is_multi_select=true` 是官方 schema 事实，未来可能出现多值；同步层仍应保留原始数组，不能按当前数据把来源契约收窄成单值。

### 1.2 枚举混合语义

筛选器当前提供 21 个“阵营”值：

| 编辑分类           | 数量 | 官方枚举                                                                                                       |
| ------------------ | ---: | -------------------------------------------------------------------------------------------------------------- |
| 地点、世界或仙舟舰 |    9 | 太空站「黑塔」、雅利洛-Ⅵ、仙舟「罗浮」、匹诺康尼、仙舟「朱明」、仙舟「曜青」、翁法罗斯、仙舟「玉阙」、二相乐园 |
| 组织或人物群体     |   10 | 星穹列车、星核猎手、星际和平公司、纯美骑士团、假面愚者、流光忆庭、巡海游侠、自灭者、博识学会、焚化工           |
| 兜底或跨作品类别   |    2 | 银河、异界                                                                                                     |

这里的分类是 Fireflydle 对标签语义的分析，不是接口提供的类型。接口只给出统一的 `character_factions`。

这会造成直接判题时的不对称：砂金被标为组织“星际和平公司”，而希儿被标为地点“雅利洛-Ⅵ”；两者不是同一分类维度。星期日和知更鸟当前甚至没有值。由此不能把该数组直接改名成 `factionIds` 或 `regionIds`。

## 2. NPC 列表与详情字段

### 2.1 覆盖率

中文 `menu_id=105` 当前返回 436 条。逐页读取详情基本信息后的覆盖为：

| 字段                  | 非空条目 | 覆盖率 |
| --------------------- | -------: | -----: |
| 列表 `npc_factions`   |      429 |  98.4% |
| 详情 `阵营`           |      429 |  98.4% |
| 详情 `身份`，排除 `-` |      409 |  93.8% |
| 详情 `派系`，排除 `-` |        1 |   0.2% |

唯一有详情 `派系` 的样本是[帕姆（581）](https://wiki.hoyolab.com/pc/hsr/entry/581)，值为“无名客 - 开拓”。因此 NPC 详情的 `派系` 不能作为通用同步字段。

列表 `npc_factions` 只有 8 个值：匹诺康尼 162、仙舟「罗浮」118、贝洛伯格 73、太空站「黑塔」54、翁法罗斯 10、星际和平公司 9、星穹列车 2、仙舟「曜青」1。它明显承担浏览分组职责，并不全是严格组织归属。

### 2.2 列表与详情冲突

429 个两层都有值的条目中，有 54 个字符串不相等：

- 51 个只是“太空站「黑塔」”“空间站「黑塔」”“「空间站」黑塔”等写法不同，可由审核后的别名归一化解决。
- 3 个是实质语义冲突：捷德列表为太空站「黑塔」、详情为匹诺康尼；霍华德列表为仙舟「罗浮」、详情为星际和平公司；陶德列表为仙舟「罗浮」、详情为博识学会。

霍华德和陶德说明列表值可以表达“在哪个区域的内容中出现”，详情值则表达“属于哪个组织”。所以列表层与详情层不应互相覆盖。

另有两个详情有阵营但列表为空：螺丝咕姆为天才俱乐部，“信使”为流光忆庭；两个列表有阵营但详情为空：伦纳德和呜呜伯。这进一步证明必须保留来源层级和缺失状态。

### 2.3 `身份` 为什么不是分类字段

详情 `身份` 的 409 个非空值包括：

- 组织职位：“星际和平公司专员”“地火领袖”“应物科 1 级科员”；
- 会员编号：“天才俱乐部 #76 号会员”；
- 物种或对象：“宠物狗”“空间站机器人”“阮·梅造物”；
- 临时状态或玩笑：“忙碌中”“已连接”“他不愿透露姓名”；
- 叙事称谓：“忆者”“贴身机器卫士”。

这些值没有统一粒度、封闭枚举或稳定语义。它适合显示和检索，不适合作为 Wordle 的集合比较列。若未来需要“物种”“职位”等字段，应分别定义并单独调研，不应先造一个万能标签桶。

## 3. 派系菜单 `menu_id=120`

### 3.1 结构与覆盖

当前列表为中文 36 条、日文 36 条、英文 34 条；英文缺无漏净子（4056）和绝灭大君（4000）。筛选器只有 `faction_type`，界面文案为“命途”，单选，共 17 个枚举。

36 个详情页的基本信息覆盖为：

| 键       | 页面数 |
| -------- | -----: |
| 名称     |     35 |
| 命途     |     35 |
| 星神     |     34 |
| 关联条目 |     31 |
| 总部地点 |      1 |
| 创始人   |      1 |
| 部门     |      1 |

总部地点、创始人和部门都只出现在[星际和平公司（968）](https://wiki.hoyolab.com/pc/hsr/entry/968)。这不是一个可以泛化到全部派系的 schema。

### 3.2 关联不能自动变成层级

31 页共有 48 个“关联条目”引用，其中只有 9 个是派系页到派系页的引用。引用没有 `relationType` 或可靠方向：

- [石心十人（2402）](https://wiki.hoyolab.com/pc/hsr/entry/2402)与星际和平公司互相引用，这与上下级关系相容，但接口没有声明其关系类型。
- [无名客（962）](https://wiki.hoyolab.com/pc/hsr/entry/962)与[星穹列车（965）](https://wiki.hoyolab.com/pc/hsr/entry/965)互相引用，但两者可能是人物群体与载体/组织的关系，不能仅凭方向决定父子。
- [仙舟联盟（963）](https://wiki.hoyolab.com/pc/hsr/entry/963)关联丰饶之民；这是敌对或叙事关系，不是父子关系。
- 源究森林关联天才俱乐部和博识学会，也不能仅凭链接判断组织隶属。

所以 `关联条目` 只能作为待审核证据，不能自动导入 `parentId`。

### 3.3 相关角色不足以生成成员关系

严格名为“相关角色”的模块只出现在 6/36 个派系页，有 31 个角色形态引用、25 个唯一角色形态。扫描所有富文本后也只有 7/36 页、34 个引用、28 个唯一角色形态。

典型缺口：

- 石心十人页没有角色引用；公司页只在“游戏相关资料”中列托帕、翡翠和砂金，且没有声明三人都是石心十人成员。
- 自灭者页没有角色引用；角色菜单却把黄泉标为自灭者。
- 家族页没有角色引用。
- 无名客页列 6 个角色形态，星穹列车页列 11 个；两份清单不等价，并受同一人物不同形态影响。

因此 menu 120 可自动导入稳定页面 ID、三语名称、命途、星神和原始关联引用；父子关系、成员关系和角色主派系必须人工审核。

## 4. 地区与派系如何分离

### 4.1 能自动做什么

- 保留角色 `character_factions.values[]` 和 NPC 列表/详情原始值。
- 对纯拼写差异做审核后的 alias 归一化，例如三种“黑塔空间站”写法。
- 把 menu 120 页面作为正式派系候选词典。
- 保存所有来源的页面 ID、字段路径、抓取时间和响应哈希。

### 4.2 必须人工编辑什么

- 角色的唯一主地区，尤其是官方值为空、为组织或为“银河/异界”的条目。
- NPC 的唯一地区；不能把列表浏览分组无条件当作人物归属。
- 角色和 NPC 的唯一主派系；官方来源可能只给宽泛组织，也可能完全缺失。
- 派系的父子关系和实体成员关系。
- 跨作品角色、跨地区活动人物、长期旅行者和同一人物不同形态的归属规则。

`regionId` 的产品定义必须是“Fireflydle 为本题采用的主叙事地区”，而不是出生地、当前所在地、首次登场地或任意到访地。否则星期日、波提欧、公司成员和星穹列车成员会同时满足多个答案，唯一字段无法公平判题。

## 5. 无名客、自灭者、石心十人如何归类

三者都有官方 `menu_id=120` 派系页，所以统一作为 `FactionNode` 是最一致的做法：

- 无名客：派系节点；与星穹列车的具体关系由 Fireflydle 审核定义。
- 自灭者：派系节点；黄泉的角色菜单值提供一条官方成员分类证据。
- 石心十人：派系节点；与星际和平公司的父子关系需要引用官方页面/文本后人工确认，不能只靠无类型关联。

它们在社会学上可能分别更像旅者群体、共同处境者和公司部门成员，但 Wordle 判题需要的是稳定且玩家可理解的分类，而不是把每种世界观概念扩成一列。统一进入“派系”词典，同时保存节点类型和证据，优于另设“身份标签”。

## 6. 推荐的最小模型

```ts
type EntityWorldview = {
  // Fireflydle 审核后的唯一判题值；允许无法公平归类时为空。
  regionId: RegionId | null;
  factionId: FactionId | null;

  // 原始官方事实，只用于审计和重新生成，不直接判题。
  sources: WorldviewSourceFact[];
};

type FactionNode = {
  id: FactionId;
  names: LocalizedText;
  kind: "organization" | "collective" | "institution" | "other";
  parentId: FactionId | null;
  sourceRefs: SourceRef[];
};

type Region = {
  id: RegionId;
  names: LocalizedText;
  sourceRefs: SourceRef[];
};
```

模型约束：

1. `regionId` 和 `factionId` 各自最多一个，满足界面唯一字段要求。
2. 不增加 `identityTagIds`。
3. 地区与派系互不继承：同地区不代表同派系，同派系也不必有同地区。
4. `FactionNode.parentId` 只接受人工审核、有明确一手证据的边；官方 `关联条目`只保存为 source fact。
5. 一个实体有多个真实归属时，题池规则选择一个主派系，并把该选择明确标为 Fireflydle 编辑判断。
6. 货币战争的 `bondIds[]` 和 `rulesetId` 不进入这个模型。

### 官方事实与编辑判断的边界

| 数据                                                                       | 性质                  |
| -------------------------------------------------------------------------- | --------------------- |
| HoYoWiki 页面 ID、原始列表筛选值、详情阵营/身份/派系、派系页命途/星神/引用 | 官方事实              |
| 纯拼写 alias                                                               | Fireflydle 审核归一化 |
| `regionId`、`factionId`、派系 `parentId`、是否入题池                       | Fireflydle 编辑判断   |
| `exact/close/miss/unavailable`                                             | Fireflydle 游戏规则   |

## 7. 可解释的判题规则

### 地区

```text
exact       两者非空且 regionId 相同
miss        两者非空且 regionId 不同
unavailable 任一实体没有经过审核的 regionId
```

地区不设 `close`。同属“银河”、曾到访同一地点或来自同一仙舟联盟，都不足以形成方向明确、玩家可预期的接近关系。

### 派系

```text
exact       两者非空且 factionId 相同
close       两者非空，且审核后的派系树中一方是另一方祖先，
            或二者有同一个允许产生 close 的最近祖先
miss        两者非空且不满足 exact/close
unavailable 任一实体没有经过审核的 factionId
```

`close` 必须返回结构化原因，例如：

```ts
{
  state: "close",
  reason: {
    key: "same-faction-family",
    params: { ancestorFactionId: "ipc" },
  },
}
```

允许产生 `close` 的共同祖先必须逐节点配置。不要把所有高层命途派系或“银河”做成超级祖先，否则几乎所有角色都会变黄。

## 8. 边界案例压力测试

### 8.1 砂金、托帕、翡翠与公司普通职员

若三位角色经审核使用 `stonehearts`，则三者 `exact`；公司普通职员使用 `ipc`，与石心十人成员 `close`。该规则依赖人工确认的 `stonehearts -> ipc`，不能从 menu 120 的互链自动生成。

### 8.2 黄泉与其他虚无相关人物

黄泉的官方角色筛选值为自灭者，可使用 `self-annihilator`。不能因为另一人物与虚无命途或星神Ⅸ相关就自动 `close`；派系页的“命途”不是角色成员关系。

### 8.3 姬子、瓦尔特、帕姆与开拓者多形态

可审核为同一主派系 `astral-express`，从而 `exact`。无名客是否作为更细节点需要产品统一口径；不能让同一人物的不同战斗形态因页面引用差异产生不同派系。

### 8.4 霍华德和陶德

两人的 NPC 列表都按仙舟「罗浮」分组，详情分别属于星际和平公司和博识学会。地区可审核为罗浮，派系分别为 IPC 和博识学会。这个案例证明地区与派系必须是两列。

### 8.5 星期日和知更鸟

当前角色列表的 `character_factions` 均为空。任何地区或派系答案都必须来自其他明确一手证据并人工审核；不能因角色曾在匹诺康尼活动就静默填充。

### 8.6 波提欧、巡海游侠与“银河”

波提欧当前角色阵营为空，乱破为巡海游侠；“银河”又是另一个混合兜底标签。若审核确认波提欧属于巡海游侠，两人派系可 `exact`；地区仍可能为空或采用产品定义的主叙事地区，不能把“银河”同时当地区与派系。

### 8.7 仙舟罗浮角色与仙舟联盟

罗浮是地点/舰船，仙舟联盟是派系。景元与青雀可以同地区；若主派系进一步分别采用云骑军、太卜司等细分组织，则不应仅因都在罗浮就让派系 `close`。只有经过审核的派系祖先关系可以产生 `close`。

### 8.8 捷德

捷德列表为太空站「黑塔」，详情为匹诺康尼，且不是拼写差异。未查清官方语义前应标记 `unavailable` 或排除题池，不应由同步脚本任取其一。

## 9. 发布和维护门槛

- 同步必须保留原始数组和详情字段，不因当前单值分布丢失多值能力。
- 新增枚举先分类为地区、派系或兜底候选；未知语义阻止自动入题。
- 每个可判题的 `regionId`、`factionId` 和 `parentId` 都要有来源引用及审核记录。
- 三语名称缺失不删除已审核节点，但阻止其进入要求三语完整的正式题池。
- 规则变更生成新 manifest；历史对局绑定旧快照。
- `close` 的 golden fixtures 至少覆盖上面的八个边界案例。

最终建议是：**删除“身份标签”概念；普通世界观只发布唯一地区与唯一主派系。派系可以有受控层级，但该层级是 Fireflydle 的有证据编辑模型，不是 HoYoWiki `关联条目`的自动镜像。**
